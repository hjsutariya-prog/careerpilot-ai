# Template and Master Resume Experience Matching Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deterministically match a user's template-resume experiences to their active Master Resume experiences without exposing Master Resume content to tailoring.

**Architecture:** Add a pure matcher that builds conservative experience metadata from template headers and compares it with the stored Master Resume structure. The matcher will use exact normalized company names as the anchor, dates and titles as stronger corroborating signals, and document order only as a tie-breaker; a Convex query will apply owner and active-master checks before deriving the result.

**Tech Stack:** TypeScript, Convex queries/schema validation, Vitest, existing `ResumeBlock` and `MasterResumeStructure` models.

**Spec:** User request in this conversation: “Implement Template Resume ↔ Master Resume experience matching.”

## Global Constraints

- Use `npm.cmd` for every npm command.
- Matching is deterministic; do not call Gemini.
- Do not pass Master Resume content to production tailoring.
- Do not modify DOCX rendering, credits, block IDs, prompts, validators, or tailoring operations.
- A match is one-to-one and must prefer an unmatched result over a low-confidence result.
- Only an authenticated user's active Master Resume and their own selected template Resume may be used.
